# Real Pi end-to-end tests

This opt-in suite starts your local Pi CLI in RPC mode, loads this checkout's
extension, and lets the real parent model submit graphs. Nodes use the real model
registry and tools. It requires Node.js 22+, Git, an authenticated Pi installation,
and the repository/Pi dependencies. It incurs provider usage and is excluded from
the default unit-test command. No credentials are copied into the artifacts.

From the repository root:

```sh
npm run build
node integrations/pi/test/live/run.mjs \
  --pi /absolute/path/to/pi \
  --model provider/model
```

`--pi` defaults to `BRAID_PI` or `pi` on PATH. `--model` is explicit to make runs
reproducible. Artifacts default to a new directory in the OS temporary directory;
use `--out /absolute/path` to choose another location. Pi runs with `--offline` to
skip startup updates, but model calls still use the network and normal Pi auth.

The suite includes:

- `selective-merge`: dirty caller snapshot, independent alternatives, selective
  integration, and automatic final merge for an unconnected documentation node.
- `partial-failure`: a real write followed by an injected provider failure;
  downstream agents continue and recover the failed node's changes.
- `non-git`: read-only tools, no worktree and no automatic merge.
- `real-conflict`: the merge agent cherry-picks conflicting checkpoints, resolves
  the real Git conflict and continues the operation.
- `merge-failure`: after a real merge-agent inspection, an injected provider
  failure exercises checkpoint archival and worktree cleanup.
- `cancel`: after a real write, the recorder pauses the next provider request and
  notifies the parent, which calls `braid_cancel` and retrieves the result.
- `git-arguments`: deliberate repeated `status`/`diff` commands must be rejected;
  full status must reveal actual changes, explicit `-- status` must work, and
  available search tools must successfully find the test content.

Run one or several cases, or compare with a previous suite:

```sh
node integrations/pi/test/live/run.mjs --pi /path/to/pi --model provider/model \
  --cases git-arguments,non-git --baseline /tmp/previous-results
```

Each run saves its exact `prompt.txt`, CLI arguments, `braid-call.json`, node and
parent RPC transcripts, result, filesystem/Git checks, and assertion results.
`report.md` includes the full prompts, actual graph submissions, per-node counts,
errors and evidence links. `suite-summary.json` is machine-readable. Model
thinking blocks are omitted. Reports use Pi job status; cancellation is represented
by core `failed` + `CANCELLED` and Pi `cancelled`.

All scenario prompts and report templates are in English. The six original
scenarios retain their test instructions from the earlier live suite, translated
from Chinese. Reports embed the exact prompt used for each run and compare prompt
text with the baseline; runs made before the translation will show a mismatch.
Counts and latencies vary because graph prompts and tool choices are generated by
the parent model; a single comparison is not a statistical benchmark. Fault
injection never fabricates model replies. The conflict itself is produced by
actual Git commands.

Completed cases in an existing `--out` directory are reused; choose a new output
directory for an independent rerun. Recompute assertions and the report without
calling a model:

```sh
node integrations/pi/test/live/run.mjs --out /tmp/results --analyze
```

A nonzero exit indicates a missing run or failed assertion. Node worktrees are
expected to be removed. Fixture repositories and recovery refs remain in the
artifact directory for inspection. Do not run multiple drivers against the same
output directory concurrently. This suite does not exercise process crashes,
cross-process merge locking, cleanup permission failures, or interactive TUI.

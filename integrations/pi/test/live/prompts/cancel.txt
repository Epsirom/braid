Use braid to test cleanup when a running graph is cancelled. Submit exactly one graph. The parent agent must not modify files or take over integration.
The graph must contain only one execute node, worker, with no edges. worker must first use write to create cancelled.txt with the exact content "recoverable cancelled change\n", then read it to verify the content. After this real write, the test recorder will pause the node before its next provider call and send a live-test-ready message to the parent agent. This pause creates a predictable cancellation window for the test.
After submitting the graph, end your current response and wait for live-test-ready. Upon receiving it, immediately call braid_cancel with the jobId returned by submission. Do not cancel early. Then wait for braid's completion reminder and call braid_status. Do not resubmit the graph or add a merge node to integrate changes. Set only nodeTimeoutMs=180000 and graphTimeoutMs=480000 in options.
In the final report, state the actual cancellation status, whether any unrequested integration occurred, whether unfinished changes were preserved in a checkpoint, whether the node worktree was cleaned up, and whether user.txt and notes.txt in the source repository were preserved.
